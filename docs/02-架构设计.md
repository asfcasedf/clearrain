## 四、认证流程

### 4.1 JWT 配置

- Access Token：有效期 **30 分钟**
- Refresh Token：有效期 **7 天**
- 前端存储：`localStorage`（access）+ `localStorage`（refresh）
- 请求头：`Authorization: Bearer <access_token>`

### 4.2 登录流程

```
学生/管理员输入学号+密码
        │
        ▼
POST /api/v1/auth/login/
        │
        ▼
后端校验 → 生成 access + refresh
        │
        ▼
返回 {access, refresh, user}
        │
        ▼
前端存 localStorage，跳转首页
```

### 4.3 刷新 Token

```
前端请求收到 401
        │
        ▼
POST /api/v1/auth/refresh/  {refresh}
        │
        ▼
返回新 access → 重放原请求
        │
        ▼
refresh 也过期 → 清 token，跳登录
```

### 4.4 权限模型

- 学生：`is_staff=False`，仅访问本人数据
- 管理员：`is_staff=True`，可访问管理端接口
- 接口权限：
  - 公开：`/auth/login/`、`/auth/register/`、`/auth/refresh/`
  - 需登录：其余接口默认 `IsAuthenticated`
  - 需管理员：`/admin/*` 加 `IsAdminUser`

- 启动：`python manage.py runserver --settings=config.settings.dev`

## 六、统一响应与错误处理

### 6.1 响应格式

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录 / Token 失效 |
| 403 | 权限不足 |
| 404 | 资源不存在 |
| 500 | 服务器异常 |

### 6.2 分页响应

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "results": [],
    "total": 100,
    "page": 1,
    "page_size": 10,
    "total_pages": 10
  }
}
```

### 6.3 全局异常处理器

- 捕获 `APIException`、`IntegrityError`、`DoesNotExist`、通用 `Exception`
- 统一返回 `{code, msg, data}`，data 为 null
- 记 error 日志（含 traceback）

## 七、部署方案（生产）

1. 后端：Gunicorn + Django，监听 `0.0.0.0:8000`
2. 前端：`npm run build` 产出 `dist/`，Nginx 托管静态资源
3. Nginx 反向代理 `/api/v1/*` → `http://127.0.0.1:8000`
4. 数据库：MySQL 8.0
5. 静态资源：`collectstatic` → Nginx 托管
