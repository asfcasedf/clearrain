# 07 — 编码规范

> 项目：晴雨（ClearRain）
> 版本：v1.0
> 说明：本文档汇总 `.cursor/rules/` 下的 6 份规则，作为编码强制规范。完整规则以 `.cursor/rules/*.mdc` 为准。

---

## 一、工作流规范（对应 00-ai-coding-workflow.mdc）

### 1.1 小步快跑
- 每次只生成一个原子单元（≤ 50 行）
- 分层开发顺序：`Model → Serializer → Service → View → URL → 前端请求 → 前端页面`
- 每层验证通过后再进入下一层，禁止带 bug 往下写

### 1.2 修改已有代码
- 精准截取报错范围，不喂整个文件
- 修改前声明影响范围，修改后输出变更清单表格
- 同一错误修 3 次未解决 → `git checkout .` 回滚

### 1.3 Git 提交
- 单个 commit ≤ 500 行，超过拆分
- 提交前 `git diff` 确认范围
- 禁止无意义 message

## 二、全栈编码规范（对应 01-coding-standard.mdc）

### 2.1 环境锁定（禁止变更）
- 后端：Python 3.13、Django 5.1、DRF 3.15、SimpleJWT
- 前端：Node 24、Vue 3.4、Vite 5、Vue Router 4、Pinia、Axios、ECharts 5
- 数据库：SQLite（开发）/ MySQL 8.0（生产）

### 2.2 统一响应
```json
{ "code": 200, "msg": "中文提示", "data": {} }
```
code: 200成功 / 400参数错误 / 401未登录 / 403权限不足 / 404不存在 / 500异常

### 2.3 RESTful 路由
- 前缀 `/api/v1/`，资源复数命名
- 分页参数 `?page=1&page_size=10`，返回 `{results, total, page, page_size, total_pages}`

### 2.4 数据库规则
- 全栈蛇形命名（`user_id`），禁止驼峰
- models.py 是唯一数据源，禁止手动改库
- 增删改必须 `@transaction.atomic`
- 禁止原生 SQL（除非性能问题且有注释）
- 列表查询强制分页，禁止 `.objects.all()` 全表
- 关联查询用 `select_related` / `prefetch_related`，禁止 N+1
- 批量操作用 `bulk_create` / `bulk_update`

## 三、后端 Django 规范（对应 04-django-practices.mdc）

### 3.1 分层架构
```
Model → Serializer → Service → ViewSet → URL
```
- **Model**：只定义字段、约束、关系
- **Serializer**：数据校验 + 序列化，`validate_xxx` 做字段级校验
- **Service**：业务逻辑（评分、状态变更），每个 app 建 `services.py`
- **ViewSet**：只做参数接收 + 调 Service + 返回响应，不写业务逻辑

### 3.2 安全
- 密码用 `set_password()`，禁止明文
- JWT access 30min / refresh 7d
- 所有接口默认需登录，公开接口显式 `permission_classes = [AllowAny]`
- CORS 只允许前端域名，禁止 `*`

### 3.3 序列化
- 入参、出参用独立 Serializer，禁止混用
- 敏感字段（密码、token）不写进 `fields`
- 日期时间统一 `%Y-%m-%d %H:%M:%S`

### 3.4 日志
- 用 `logging`，禁止 `print`
- 关键操作（登录、测评提交、评分）记 info 日志
- 异常记 error 日志，附 traceback

### 3.5 禁止清单
- ❌ 函数视图（FBV），必须用 ViewSet
- ❌ 在 ViewSet 里写业务逻辑
- ❌ 裸 SQL
- ❌ 明文密码
- ❌ `print()` 调试

## 四、前端 Vue 规范（对应 05-vue3-practices.mdc）

### 4.1 核心语法
- **必须** Composition API + `<script setup>`，禁止 Options API / `this`
- `ref()` 用于基本类型，`reactive()` 用于对象/数组
- 禁止 `ref({})` 包裹对象

### 4.2 请求封装
- 所有请求走 `src/api/request.js` 封装的 axios 实例，禁止裸写 `axios.get`
- 自动携带 `Authorization: Bearer <token>`，超时 10s
- 响应拦截统一处理 code 和 401（自动跳登录）
- 每个接口在 `src/api/xxx.js` 封装成函数

### 4.3 路由与状态
- 需登录路由加 `meta: { requiresAuth: true }`
- 401 自动跳转登录页
- 用户信息、token 用 Pinia store 管理
- 页面级数据用组件内 ref/reactive，不塞 store

### 4.4 组件规范
- 文件名 PascalCase：`UserCard.vue`
- props 必须定义类型和默认值，emit 必须声明
- 单文件组件 ≤ 300 行，超过拆子组件

### 4.5 UI 库隔离
- 学生端只用 Vant 4，管理端只用 Element Plus，禁止混用
- 学生端移动优先 375px，管理端 PC 优先 1366px

### 4.6 状态处理
- 每个异步操作有 loading 状态
- 列表页处理空状态
- 请求失败必须 toast 提示，禁止静默失败

### 4.7 禁止清单
- ❌ Options API
- ❌ 直接 `axios.get`
- ❌ 学生端用 Element Plus / 管理端用 Vant
- ❌ 硬编码 API 地址

## 五、UI 设计规范（对应 02-ui-design.mdc）

> ⚠️ 当前配色锁定为暖橘 `#F0814A`，待用户选定最终配色方案后同步更新本规则。

### 5.1 文案铁律
| ❌ 禁止 | ✅ 必须 |
|--------|--------|
| "用户" | "你" |
| "提交成功" | "已经记录下来啦 ✨" |
| "暂无数据" | "还没有记录 🌱 开始你的第一次自测吧" |
| "确认删除" | "确定要移除这条记录吗？" |
| "取消" | "再想想" |
| "重试" | "再试一次" |

### 5.2 结果页铁律
- 先说「这很正常」→ 再给建议 → 最后附免责声明「本测评不构成临床诊断」

### 5.3 布局
- 一屏一焦点，禁止两个 primary 按钮并列
- 拇指热区：手机端核心按钮放屏幕下半区
- 大留白：卡片间距 ≥16px，内容区 padding ≥24px

### 5.4 动效
- 慢、柔、自然，禁止弹跳/闪烁
- 允许 opacity 淡入淡出、translateY(4px) 微上浮

## 六、Git 工作流（对应 03-git-workflow.mdc）

### 6.1 分支策略
- 从 `develop` 创建功能分支，禁止在 main/master 直接开发
- 命名：`feature/xxx`、`fix/xxx`、`refactor/xxx`、`docs/xxx`

### 6.2 Commit 格式
```
<type>(<scope>): <subject>
```
- type：feat / fix / refactor / style / docs / chore / perf
- scope：backend / frontend-student / frontend-admin / config
- subject ≤ 50 字，祈使句，不加句号

### 6.3 流程
1. `git pull --rebase` 拉取最新
2. 读 `TASKS.md`，标记目标任务 🔄 进行中
3. 读对应 `docs/` 文档
4. 小步实现（≤50 行），自测通过
5. `git diff` 确认范围，分段 commit（≤500 行）
6. 更新 `TASKS.md` 状态为 ✅
7. `git push`

### 6.4 回滚
- 3 次修复失败 → `git checkout .` 回滚
- 禁止 `git push --force` 到主分支

### 6.5 .gitignore 必须包含
```
.env
__pycache__/  *.py[cod]  *.egg-info/
*.sqlite3
node_modules/  dist/
.vscode/  .idea/
.DS_Store  Thumbs.db
staticfiles/  media/
venv/  env/
```

## 七、不过度防御编程

- **信任上游**：Serializer 已校验的字段，Service 不重复校验
- **异常不吞**：只在 DB 写操作/外部调用处捕获，其余向上抛
- **不写冗余判空**：`get_object_or_404()` 后不重复 `if obj is None`
- **YAGNI**：不提前实现不存在的场景
- **注释克制**：代码自解释，只在业务规则（如反向计分）处加中文注释
- **不堆 if-else**：能用 early return 就不嵌套
